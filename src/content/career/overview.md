## 何をする人か

立林裕太朗は、**Applied AI、要件定義、System / Software Architecture、既存システムの保守・モダナイゼーション**を軸とするソフトウェアエンジニアです。  
Windowsソフトウェア開発で培った実装・保守経験を土台に、要求と技術を結び付けます。

- 業務要求を整理し、機能・非機能要件と実現方式へ具体化する
- AI・人間・既存システムの役割、責任境界、停止・引継ぎ条件を設計する
- RAG / QA、Knowledge、Context Engineering、AI Evaluation、HITLを業務に組み込む
- C# / .NETを中心に、Windows向けソフトウェアを設計・実装・評価・保守する
- 既存コードと動作を解析し、変更影響や保守上の制約を明らかにして、維持・改修・モダナイゼーションへつなげる

## 現在の専門性

技術名そのものよりも、**何を要件化し、どこに責任を置き、どう検証するか**を重視しています。

- **Requirements / Architecture：** 与えられた業務要求・業務目標を、システム要件、機能・非機能要件、責任分担、方式、検証条件へ落とし込みます。  
  AIを導入する部分と、既存システム・人間に残す処理を分けて設計します。
- **Applied AI / Knowledge：** LLM、RAG、ベクトル検索を用いたQAの検索対象、回答根拠、追加確認、回答しない条件、有人引継ぎを設計します。  
  Knowledgeの構造・更新、Context Engineering、AI Evaluation、Human in the Loopを一体で考えます。
- **Software Engineering / Existing Systems：** C# / .NET、Windowsを中心に、既存仕様の解析、変更影響分析、異常系設計、実装、評価、長期保守に対応します。  
  保守とモダナイゼーションを、互換性や運用制約を踏まえた設計問題として扱います。
- **Project / Delivery：** プロジェクト推進・PMの経験を生かし、品質・リスク・関係者間の調整を、要件と設計判断につなげます。

現在の中心的な実務範囲は、**業務要求 → システム要件 → Architecture → 実装・検証**です。  
価値発見や投資判断そのものを、すでに担当した企画実績としては扱いません。

## 技術的バックグラウンド

**2016年からソフトウェア開発に従事**しています。  
中心はC# / .NETによるWindows向け業務ユーティリティの開発・保守です。  
外部システム連携を含む複数のユーティリティについて、要件整理、設計、実装、評価、保守まで経験してきました。

長期間の保守開発では、仕様書だけでなくソースコード、UI、実動作を突き合わせ、現行仕様や依存関係を確認してきました。  
既存機能との互換性、例外・異常系、変更による波及、修正後の運用を含めて設計することが、ArchitectureとApplied AIへ取り組む際の基盤です。

Pythonは、分割仕様書の統合、調査・検証、自動化、AI活用に使用しています。  
また、複数チームが関わる開発のプロジェクト推進・PMを経験し、個別実装に加えて、全体影響、品質課題、優先順位、関係者調整を扱ってきました。

## 仕事で重視すること

- **要求と方式を混同しない。**  
  業務目標を技術名に置き換えず、必要な機能・品質・運用条件を定義したうえで方式を選びます。
- **AIの出力と判断責任を分ける。**  
  AIには探索・比較・候補生成を任せても、根拠確認、採否判断、変更の承認は適切な人間の工程に残します。
- **作って終わりにしない。**  
  現行システムの制約、Knowledgeの更新、保守・運用、評価を含めて、継続して扱える構造を重視します。

## 今後広げたい判断領域

現在は、**業務要求をシステム要件とArchitectureへ具体化し、実装・検証へつなぐ領域**が中心です。

今後はその上流にある **システム企画・IT戦略** へ判断範囲を広げたいと考えています。  
業務の価値と課題を捉え、業務要求・業務目標・KPI、システム化する範囲としない範囲、投資と優先順位を検討する領域です。

新しく作るだけでなく、**作らない・維持する・改修する・統合する・廃止する**といった選択にも、要件定義と既存システムの知見を活用したいと考えています。  
これは現在の設計・開発経験から連続する今後の方向性であり、企画判断の実績を主張するものではありません。

## 希望するRole

システム企画・業務要件とシステム要件の接続、System / Software Architecture、Applied AI、既存システムの保守・モダナイゼーションを中心に担う**技術専門職（Individual Contributor）**を志向しています。  
一つのシステムやサービスに継続して関わり、要件・方式・実装・評価・運用をつなぐ働き方が希望です。

FDE、顧客常駐や顧客折衝そのものを中心とする役割、顧客ごとの短期PoC・個別実装を反復する役割は、主な志向先ではありません。  
FDEを独立した技術能力の分類とは捉えず、企画・要件定義・設計・実装・改善を横断し得る働き方として理解しています。
