## 詳細な回答が返っても、自分が評価できるとは限らなかった

引き継ぎプロンプトと実行時の証拠を、共通ライブラリ側のCopilotへ渡した。新しい対話が、それまでの背景を知っているとは想定しなかった。途中から調査を担当する人へ説明するように、何が起き、どこまで調べ、何が残っているのかを伝えた。

以下は、引き継いだ情報と用途を説明するための整理であり、入力に必須の項目やテンプレートを示すものではない。

| 渡した情報 | 継続する調査で使う目的 |
| --- | --- |
| ライブラリ更新後のクラッシュと、その発生・再現条件 | 何を解決するための調査か、対象の現象を共有する |
| 実施済みの調査とその結果 | それまでに分かったことを前提に、次の確認範囲を決める |
| 終了処理の同期制御の不備を修正しても、クラッシュが残ったこと | 修正済みの不具合と、解決していない障害を区別する |
| 取得したクラッシュダンプやコールスタックなどの実行時の証拠 | コードから得た候補を、障害時の観測と照合する |
| 未確定の仮説と、次に確認したい事項 | 原因が確定したと扱わず、追加調査を進める |

Copilotには関連コードの横断調査や更新前後の比較を依頼し、初期化・終了処理、呼び出し経路、リソースの保持・解放などを調べさせた。返ってきた説明には、具体的な原因候補と対応案が含まれていた。

Copilotは、共通ライブラリ側のメモリ管理に関する問題を原因候補として挙げた。発見時点では、内部構造を十分に理解していない私には、その修正案の正しさや他機能への影響を独力で評価できなかった。

修正案の採用は決めず、Copilotへ問題点と原因候補を整理させ、追加で確認すべき事項を洗い出した。

## 証拠と仮説を照合し、担当チームの判断につなぐ

実行時の証拠としてクラッシュダンプやコールスタックを確認し、不正なポインタ状態が観測された。これは観測された事実だが、その状態に至った原因や、Copilotが挙げたメモリ管理の候補と対象クラッシュとの因果関係までは確定できなかった。私は証拠と仮説を照合し、不足する証拠や、内部実装に詳しい担当者の追加確認が必要な事項を整理した。

私は、確認済みの情報、実行時の証拠、調査結果、原因候補、追加で確認してほしい事項をまとめ、担当チームへ渡した。原因候補は修正指示ではなく、担当者が調査を進めるための参考情報として提示した。

私の担当範囲でのクラッシュ調査は、この引き継ぎまでで区切った。

その後、Copilotが指摘した問題は、実在するメモリリークのバグとして確認され、修正された。**修正が必要なバグを発見した一方、そのバグは当初のクラッシュの原因ではなかった。** 発見時点の原因候補と、その後に確認されたバグの存在・修正結果は分けて捉えている。

責任分担の一般的な整理は、[AI出力の責任境界とHITL](/evaluation-hitl/responsibility-and-hitl/)を参照してほしい。
