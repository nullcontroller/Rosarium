# 専門領域と主分類

分類の正本は `src/data/knowledge-domains.mjs`。URLや使用技術ではなく、本文の中心的な問い・結論・読者が判断できることから主分類を一つ決める。

| 領域 | 中心的な問い | 対象 |
|---|---|---|
| IT戦略・企画 | 何を、なぜ、どこまで実現するか | 価値、業務要求、構想、投資・KPI・範囲、維持・刷新・統合・廃止の判断 |
| DX | 業務・組織・価値をどう変革するか | 業務改革、AI活用・協働、教育、知識共有、定着・改善、ECRS |
| システム設計 | 要求をどのようなシステムとして実現するか | 要件、方式・構成・データ・連携・品質・移行・運用。RAG、Context、Evaluation、HITL、エージェントの実現方式も含む |
| AI・数理 | AIはどのような数学的・計算的原理で成立するか | 確率・統計、分布、最適化、学習・推論、モデルやアルゴリズムの基礎 |
| 事例 | 具体的な課題にどう判断・対応したか | 実務経験と仮想設計を区別。事例の正本を保ち各領域から参照する |
| キャリア | 著者は何を経験し、どこへ進むか | 現在の担当・実績と将来の志向を区別 |

AIを題材にすることや数式を含むことだけではAI・数理に分類しない。品質保証・権限・検索やコンテキストの構成が中心ならシステム設計。導入・教育・業務運用ならDX。投資・事業価値の判断ならIT戦略・企画とする。

Book・連載は主題と一体性を確認する。「AI活用の本質を問う」は目次と全6回をDXに保ち、事業価値の回などを他領域から参照する。既存のlayer、section、entry_points、primaryCategory、ai_themeは内部の役割や既存テーマ・互換情報であり、これらだけから現行の主分類を推測しない。

新規記事は本文を確認して主分類と理由を共通定義へ登録する。未定義記事をAIへ自動分類しない。同じ本文を複製した別URLは作らない。関連付けは主分類とは分けて共通定義へ記録し、記事の正規階層を変えない。

退役・旧前提の記事はアーカイブで保全する。品質監査の維持・改訂・統合・退役候補は別の評価軸であり、分類変更を処遇実行の承認とみなさない。候補の原稿を独断で改訂・統合・退役させない。

論理分類・共通ナビゲーションだけの変更で記事本文の更新日を一括変更しない。入口の説明や掲載内容が変わったページは、Authoring Guideに従って実際の改訂日を更新する。GARDEN NOTESには実際の公開日に同日エントリーの独立トピックとして追加する。

検証では主分類の定義漏れ、現役記事のカテゴリ到達性、表示と検索・パンくずの一致、URL・本文・公開日・公開状態の保護を確認する。
