# Rosariumのページ閲覧分析

本番の通常閲覧では、ページごとに`page_view`を1回送信します。
`config`の自動page_viewは無効にしています。現在は通常のHTML遷移であり、Astro ClientRouterは使用していません。
互換redirect・noindexページは除外し、遷移先を計測します。
今後ClientRouterを導入する場合は、この実装に遷移イベント対応を加え、以下の履歴変更による自動計測と重複しないことを再確認してください。

## GA4管理画面で必要な設定（コードでは未実施）

「管理 → データの表示 → カスタム定義 → カスタムディメンションを作成」で、スコープを「イベント」として登録します。

| 表示名 | イベントパラメータ | 用途 |
| --- | --- | --- |
| コンテンツ種別 | `content_type` | 記事・Case・Careerなどの比較 |
| 主分類 | `primary_category` | 既存の主カテゴリ・AI設計テーマによる比較 |
| コンテンツ領域 | `content_domain` | AI・DX・Case・Careerの比較 |

`article_slug`はページパスで代替できるため、初期設定では登録不要です。
`obsolete_status`は旧事例を分けて分析したい場合のみ、イベントスコープで追加します。
副分類は送信しません。AIとDXの両方に関係する記事も、`primaryCategory`がある場合はDXの主分類として集計します。

「管理 → データストリーム → Webストリーム → 拡張計測機能」のページビュー詳細設定で、
「ブラウザの履歴イベントに基づくページの変更」をオフにしてください。
`send_page_view: false`だけでは、拡張計測の履歴変更イベントは無効になりません。
図や目次のアンカー移動を別のpage_viewとして数えないための設定です。

ページ閲覧だけを分析する場合、拡張計測のサイト内検索・フォーム・離脱クリックは不要です。
これらはコードで送るpage_viewとは別の自動イベントなので、任意の検索語やリンクURLを収集しないようオフにしてください。
今回、GA4管理画面の既存設定は変更・確認していません。

## レポートの見方

- 「レポート → エンゲージメント → ページとスクリーン」で、ページタイトルまたはページパスを選び、表示回数・アクティブユーザー・平均エンゲージメント時間を比較します。
- 「探索 → 自由形式」でページパス、主分類、コンテンツ領域を行にし、表示回数・ユーザー数・エンゲージメント時間を比較します。
- LinkedIn流入は「セッションの参照元 / メディア」を`linkedin / social`で絞り、ランディングページとページパスを比較します。
- 検索で最初に読まれるページは、自然検索のセッションをランディングページ別に比較します。
- 次に読んだページの順序は「探索 → 経路データ探索」で確認します。

管理画面での登録後、レポートへの反映には時間がかかります。
公開後はRealtimeまたはDebugViewで、通常ブラウザからのpage_viewとパラメータを確認してください。
ローカル環境・自動操作ブラウザは計測されないため、そこでRealtime確認はできません。

## URLとプライバシー

`page_path`にはqueryとhashを含めません。
`page_location`には`utm_source`・`utm_medium`・`utm_campaign`だけを残します。
値は英数字・ハイフン・アンダースコア、80文字以内に限定し、メールアドレスや自由入力は引き継ぎません。
UTMには個人情報を使わず、`linkedin`・`social`・`rosarium`などのキャンペーン識別子を使ってください。
参照元URLはoriginだけを送り、検索語やqueryを含む詳細URLは送りません。
独自のユーザーID・IP・fingerprintは追加していません。
